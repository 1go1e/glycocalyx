## 1. 先講一個上一批留下的缺陷：37 列的 `source_ref` 格式錯誤

本批開工掃描既有列時發現，**§5B 的 37 列 `source_ref` 寫的是 `5.5`，
而不是 `glycocalyx/heparanase#5.5`**。

成因是寫入腳本裡把來源節號的常數定義成裸節號而未加檔案前綴，
治療總表那一批的每一列都套用了它。

〔注意〕**這批東西通過了全部七項驗收。** 列數、欄數、排序、無重複、
無 BOM、無 CRLF、SCHEMA §9 四欄值域檢查——全部通過，
因為 §9 檢查的是 `claim_type`／`status`／`tier`／`priority` 四個封閉值域，
而 `source_ref` 是自由文字欄，**沒有任何檢查涵蓋它的格式**。

〔推論〕這與 `STATUS.md` §7 記錄的兩起事故（v8 的 `fact` 值不在合法值內、
2026-07-30 的編碼損毀）是同一族：*所有既有檢查都通過，而東西是壞的*。
但成因更基本——前兩者是規格與實作不一致，本例是**規格根本沒說到那個欄位**。
`SCHEMA.md` §2 明確定義了 `source_ref` 的格式（`{目錄}/{檔名}#{節號}`），
但 §9 的值域檢查沒有把它納入。**規格寫了，檢查沒驗。**

已於本批修復 37 列（`5.5` → `glycocalyx/heparanase#5.5`），
並在本批的驗收中加入第五項檢查：每個 `source_ref` token 必須同時含 `/` 與 `#`。

**待核准**：把該檢查正式寫進 `SCHEMA.md` §9。這會是 schema v10——
不改欄位結構，只增加一項驗收條件。提案未寫，等你決定要不要開。

〔推論〕修復本身是無爭議的——SCHEMA §2 已有明文格式，37 列與之不符，
改回符合格式不涉及任何判斷。故本批直接執行未停下等核准；
需要核准的是**新增檢查**，那才是規則變更。

## 3. 抽取時發現的原文問題

### 3.1 試驗期別：第五個表述出現，且方向可以定案了

`STATUS.md` §3.20 追蹤的這條線，到本批集滿五處：

```
§3.5      Roneparstat 與 PG545「已進入人體第一期試驗」        （在 DR 段落內）
§4.5      同兩化合物「已進入人體第二期試驗」                  （在 DN 段落內）
§5.5 總表 非抗凝修飾肝素「Phase II 進行中」
§6.5 表   SST0001（Roneparstat）「Phase II（胰腺癌、DKD）」
管線總表  Roneparstat「Phase I（完成）Phase II（中止或未繼續）」
```

〔推論〕**管線總表這一處的可信度高於前四處，而且它給出了解釋。**
理由有三：它具名試驗編號（NCT01764880）、具名開發公司（Leadiant Biosciences，
前 sigma-tau）、並記錄了停滯原因（腫瘤療效有限）。前四處都只給期別，無其他可核對的細節。

更關鍵的是**管線前言直接說明了前四處為何會錯**：
「糖尿病腎病變/視網膜病變/神經病變領域目前僅有動物/前臨床數據，尚未有正式人體試驗」。
Roneparstat 與 PG545 確實進了人體試驗——**但那是腫瘤適應症的試驗**。
§3.5 與 §4.5 把腫瘤試驗的期別寫進了糖尿病併發症的段落。

這是 `STATUS.md` §3 已有的一個型態的實例：**數值被跨疾病脈絡挪用**。
本例挪的不是數值而是試驗階段，但機制相同——同一個事實在正確的脈絡下為真，
搬到另一個脈絡就成了假。

已建 `6.3-diabetic-complications-no-human-trial` 與
`6.3-roneparstat-phase1-complete-phase2-halted`，兩列與既有四列互相標註。
**實際定案留給回填**——本批不做檢索，上述為推論而非判定。

### 3.2 Sulodexide 的機制在同一份文件裡自相矛盾

```
§5.5 總表   「直接補充HS類似物 + 強力抑制heparanase（IC50極低）」
§6.7        「其主要機制為補充GAGs而非純粹抑制heparanase」
管線總表    「部分抑制heparanase + 補充HS」
```

三處對同一個藥的機制描述，抑制強度從「強力（IC50 極低）」到「部分」到
「並非純粹抑制」，遞減。三列已互相標註。

〔推論〕這一組與 §5A 提出的預判（**表格給的最保守、結論給的最寬**）**方向相反**——
本例最寬的是 §5.5 的表格，最保守的是 §6.7 的文字段落。
預判在 5B 命中第二次後，本例是第一個反例。
修正後的說法應該是：**同一份文件裡，離該主題最近的那一處通常最保守**。
§6 是 heparanase 專論，Sulodexide 在此是被審視的對象；
§5.5 的治療總表裡它是被推薦的方案之一。立場決定強度，位置只是相關而非成因。

### 3.3 數量差一個數量級

```
§6.6        「目前全世界至少20個以上heparanase抑制劑進入臨床試驗階段」
管線總表    列出 6 個化合物，其中 3 個已終止、1 個仍在前臨床
§6.7        「至少5–8個學術/生技公司項目在IND-enabling階段」（尚未進入臨床）
```

同一節內，總結說 20 個以上進入臨床，而自己的表列出 6 個、其中只有 2 個仍在推進。
5–8 個 IND-enabling 的項目按定義尚未進入臨床，相加也補不上差距。

三列已互相標註（`6.3-heparanase-inhibitors-20-plus-trials`、
`6.3-next-gen-inhibitors-5-8-ind-enabling`，與管線表各列）。

### 3.4 同一化合物被算成兩個

管線總表第 2 列明寫「Pixatimod (PG545, PGN626)」——三個代號同一化合物。
而本檔他處（`6.5` 表、§2.5、§3.5、§4.5）把 PG545 與 Pixatimod **並列為兩個藥名**。

〔注意〕這會影響 §3.3 的計數：若各處的並列都是同一化合物被計兩次，
「20 個以上」的來源之一可能就是這種重複計數。
已建 `6.3-pixatimod-pg545-same-compound`，該列查證後可一次澄清多處。

### 3.5 M402 的狀態衝突

§2.5 把 M402 列為「二期試驗中」的未來候選藥物；管線總表稱 Necuparanib（M402）
的 Phase I/II 因中期無效分析未達療效，**2016 年即已中止，開發完全終止**。

已於 `6.3-necuparanib-phase2-futility-halted` 標註。與 §3.1 同族——
既有列 `6.3-noncoag-heparin-inhibitor` 把 M402 與 SST0001 併稱為可抑制 heparanase
的衍生物，未觸及開發狀態，故不衝突；衝突的是 §2.5 的「試驗中」表述。

### 3.6 雌激素的跨文件張力

```
§6.4 表      雌激素誘導 heparanase 5–20 倍（ER 結合 HPA 啟動子，括註「乳癌」）
v3 → 4.2.3   雌激素保護糖萼（4.2.3-estrogen-protection）
```

一處雌激素誘導降解糖萼的酵素，一處雌激素保護糖萼。

〔推論〕兩者未必矛盾——`6.4` 的括註「（乳癌）」限定了場景，
而 v3 的保護效應講的是血管內皮。同一個荷爾蒙在不同組織經不同受體亞型
產生相反效果並不罕見。記錄它的理由是**這是本帳本首次出現跨文件的方向性張力**：
既有的跨文件問題都是同一數值的不同版本，本例是同一因子的相反效應。
兩列已互相標註。

### 3.7 化學修飾的描述不一致

§5.5 總表稱非抗凝修飾肝素為「N-**去硫酸化**/乙醯化肝素」，
管線總表稱 Roneparstat 為「100% N-**乙醯化**, glycol-split 非抗凝肝素」。
去硫酸化與乙醯化是不同的化學修飾。已於
`6.3-roneparstat-n-acetylated-glycol-split` 標註。
