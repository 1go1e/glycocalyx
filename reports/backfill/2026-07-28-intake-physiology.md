## 3. 第三個內部矛盾（新發現）

提案 §2 記錄了兩項自我矛盾。本批次讀全文時發現第三項：

| 位置 | 腦微血管糖萼厚度 |
|---|---|
| L12（正文，區域異質性） | **1-3 μm**，血腦屏障的一部分 |
| L154（檢視段） | 年輕小鼠約 **0.54 μm**，老化降至 **0.23 μm**（宣稱出自 Nature 論文） |

〔推論〕**同一份文件對同一血管床給出相差一個數量級的兩個厚度**，且未察覺衝突。
L154 明確標示為小鼠、且分年輕與老化兩組，L12 未標示物種與年齡。

〔文獻〕`2.2-brain-1-3um` 現為 `unverified`，是 STATUS §4 下一批的優先條目。

〔推論〕這對下一批的查證有直接影響：**若實查發現腦微血管的活體測量落在次微米級，
`2.2-brain-1-3um` 的 1-3 μm 就可能與 `2.1.1-extreme-11um` 同型**——
一個被放大且脫離原始樣本條件的數值。查證時應同時檢索小鼠腦微血管的直接測量值。

依 SCHEMA §2 認定規則，L154 的 0.54/0.23 與 `2.2-brain-1-3um` 是
「同一指標但數值不同」，屬**不同條**，應各自建列並互相標示——見 §4。

## 4. 未完成：淨新增主張建列受阻

### 4.1 阻礙

`claim_id` 格式為 `{section}-{slug}`，且 SCHEMA §2 規定：

> `section` 欄的值必須等於 `source_ref` 第一個 token 的節號部分。

對 `intake/` 文件而言，「節號」是行號標籤（`L154`）。照規則執行會產出
`claim_id = L154-brain-mouse-0.54`、`section = L154`。

〔推論〕這會破壞 ledger 的 `section` 軸。目前 97 條的 `section` 是**主題座標**
（2.1.1 = 厚度、5.5 = 生物標記），排序後同主題相鄰，STATUS §4 的批次劃分也依賴它。
混入 `L154` 這類值之後，排序失去意義，批次無法依主題劃分。

〔推論〕但直接把 `section` 填成主題所屬的 v3 節號（如 `2.2`）會**違反 SCHEMA §2**，
而 `CLAUDE.md` 第 2 條規定 SCHEMA 唯讀、變更須經提案。故本批次停在此處。

### 4.3 需要的 SCHEMA 變更（另案）

〔推論〕建議在 SCHEMA §2 補一則例外：

> 當 `source_ref` 第一個 token 的 `{doc}` 位於 `intake/` 之下時，
> `section` 取該主張**主題所屬的受追蹤文件節號**，而非 intake 檔的位置標籤。
> 理由：`section` 是主題座標，批次劃分與排序依賴它；
> intake 檔的位置標籤不承載主題資訊。
