## 1. 寫本單時發現的問題：條文無處可放

政策提案 §7 原本寫「SCHEMA 增訂原文措辭條款，`schema_version` → 6」。
實際要落筆時撞到兩件事，都指向同一個結論：**SCHEMA.md 不是這條規則該待的地方。**

### 1.1 SCHEMA.md 的適用範圍不含原文

```
applies_to: ledger/claims.csv
```

檔頭第一行就寫死了。把管 `source/` 的條文塞進去，等於讓一份宣稱只管一個檔案的規格
去管三個它沒宣告的檔案。而且 `schema_version` 是 `claims.csv` 的格式版本——
原文措辭改變不影響 CSV 的任何一個欄位，遞增版本號會讓 `CHANGELOG.md` 出現
一筆「什麼欄位都沒動」的紀錄。

### 1.2 更嚴重的：現行的原文規範已經放錯地方了

原文目前唯一的規範是**標註格式**，它存在

```
reports/revisions/2026-07-27-source-2.1.1-thickness.md §2
```

這份檔案依 STATUS §3.8 屬於**歷史紀錄**（已核准提案），明文規定「不改，改了就失真」。
但它同時是一條**活規則**，後續每次標註都要照它執行。

證據是 2026-07-29 已經撞到過：表格標註格式在該檔沒有正面規定，補的方式不是修改它，
而是在 STATUS §5「已定調的政策」另寫一段，並附註「此規範不回頭改寫該檔」。

〔推論〕於是同一條規則現在分散在兩個地方：散文段落的格式在提案檔裡、
表格的格式在 STATUS 裡，而 STATUS 是每批都在改的動態檔。
再補第三次時它會落到第三個地方。這已經不是存放位置的美觀問題，
是**執行者找不齊規則**的問題。

## 1. 三種允許的改動類型

| 類型 | 動到原句 | 需要的前置 |
|---|---|---|
| **標註** | 否——原句原樣保留，標記以獨立段落加在其後 | ledger 有對應判定 |
| **改寫** | 是——整段重寫 | 該段觸發 §2.4 的密度條款，或另有核准 |
| **刪除措辭** | 是——只刪字，不重組句子 | 符合 §3 的限定條件 |

除此之外的原文改動一律不允許，包括「順手修正錯字」。

## 2. 標註

收攏自 `reports/revisions/2026-07-27-source-2.1.1-thickness.md` §2
（核准 2026-07-28，核准為通用規範）與 STATUS §5「已定調的政策」表格條款
（人工裁示 2026-07-29）。上述兩處為歷史紀錄，不因本檔而修改。

1. 查無出處的數值**一律標註，不從原文刪除**（人工裁示 2026-07-27）
2. 三種標記對應 ledger 的 status：

   | 標記 | 對應 status |
   |---|---|
   | `⚠️ 〔查無出處｜{claim_id}｜{日期}〕` | `unsupported` |
   | `〔條件限定｜{claim_id}｜{日期}〕` | `partial` |
   | `〔有爭議｜{claim_id}｜{日期}〕` | `contested` |

   `verified` 與 `unverified` **均不標註**——尚未檢索不等於有問題，
   標了會稀釋真正的警示
3. **標記不得刪除或改寫原句。** 原句原樣保留，標記以獨立段落加在其後
4. 若同一段落需要三個以上標記，代表該段應整段改寫，另寫修訂單，不靠標記硬撐
5. **表格**：新增「查證狀態」欄，不用儲存格內尾隨、不用表格下方附註。
   原有欄位與所有數值一字不動，標記寫進新增欄。
   「段落」在表格上**以整張表為單位**——四列的表有四個標記即觸發第 4 點

〔推論〕第 3 點是整套政策能否成立的關鍵：允許「標註時順手改一下」，
標註與改寫的界線會在幾次批次內消失。

## 3. 刪除措辭

新增於 2026-07-30，依 `reports/revisions/2026-07-30-rhetoric-policy.md`（核准 2026-07-30）。

### 3.1 只有一類措辭可以刪

**純評價性時間形容詞**：`最新`、`近年`、`近期`、`最近`、`截至`、
`新興`、`新近`、`目前`、`當前`。

限定條件，三者須同時成立：

1. 刪除後句子仍然通順
2. 刪除後語意不變
3. 該處**未同時**命中 §3.2 的任何一類

不成立時**不刪**，改依 §3.2 處理。

```
可刪：近年來的糖生物學研究將焦點轉向「硫酸化品質」
    → 糖生物學研究將焦點轉向「硫酸化品質」

不可刪：eGC 降解目前被公認為敗血症、糖尿病中的早期損傷
        「目前」是可刪類，但「公認」屬 §3.2，整句依 §3.2 處理
```

### 3.2 不可刪，改為抽成 claim 去查

以下三類**原句一字不動**，把宣稱本身抽成一條 claim 走回填流程，
依 `SCHEMA.md` §6 寫成可查核形式，查不到具名來源即 `unsupported`，
再依 §2 加標註。

| 類 | 例 | 為什麼不能刪 |
|---|---|---|
| **年份＋文獻類型** | 「2025 年的薈萃分析指出」 | 年份是該句僅存的溯源線索，刪掉就再也追不回來 |
| **未具名權威宣稱** | 「國際共識」「新典範」「臨床標準」「金標準」 | `SCHEMA.md` §6 已明文規定處置方式 |
| **無主詞措辭** | 「研究顯示」「文獻報告」「一般認為」 | 同上 |

〔推論〕年份那類的毛病不是「有年份」，是**只有年份**——沒有作者、沒有期刊、
沒有識別碼。它與未具名權威是同一個問題，只是宣稱的載體換了。
把它當措辭刪掉，等於把一個可查證的宣稱變成不可查證的。

### 3.3 一句同時命中多類時的優先序

```
未具名權威 > 年份＋文獻類型 > 無主詞措辭 > 純評價性形容詞
```

以最重的一類為準。一旦決定不動原句，句中的可刪形容詞也一併留著——
否則會出現「同一句刪了一半」的狀態，日後無從判斷是有意還是漏改。

## 4. 檔頭的收錄基準

三個受追蹤檔的標頭各加一行：

```
> 本檔為 LLM 產出文件，2026-07-28 收錄。文中未標註年份的時間表述以此日為基準。
```

這處理的是**未來新增**的時間形容詞，不取代 §3.1 的刪除。
