## 1. 問題

SCHEMA §4 的 `evidence` 只有兩種 token 語意：無前綴＝支持，`!` 前綴＝反駁。
但回填實務中反覆出現第三種文獻——**既不支持也不反駁，卻是該列上資訊量最高的一筆**，
因為它指出原主張是從哪裡漂過來的。

這類文獻目前只能落進 `note` 的自由文字，無法被機器讀取、無法跨列比對、
無法回答「哪些主張的漂移來源已經定位」這個問題。

**六筆樣本**（2026-07-29 起累積，散落於四列）：

| # | 所在列 | 文獻 | 不對位的維度 |
|---|---|---|---|
| 1 | `2.2-sepsis-shedding-30min` | `PMID:17923576` 等四筆 | 取樣點不夠早，不足以反駁 |
| 2 | 同上 | 缺血再灌流兩筆 | 反駁的是歸屬而非現象 |
| 3 | `2.2-sdc1-halflife-2-8h` | `PMID:1533636`、`PMID:11755208` | 量的是別的分子、別的細胞 |
| 4 | 同上 | 其餘 HSPG 周轉文獻 | 同上 |
| 5 | `5.3-pbr-precedes-cognitive-2-3y` | `PMID:39494362` | 別的分子（CSF N-醣鏈）、別的方法（ELLA 非 PBR）、別的量（軌跡提前量非前導時間） |
| 6 | `4.2.3-hrt-rct-2025` | `DOI:10.14814/phy2.70428` | 年份、規模、設計、族群、終點、方向全中，**只有介入不對** |

〔推論〕第六筆改變了提案的語意範圍。前五筆的共同點是「量錯了別的東西」，
第六筆是「量對了東西但用錯了藥」。若把新語意定義為「量測對象不同」會**漏掉第六筆**；
必須定義為「**不足以支持或反駁本主張，但與其來源相關**」才涵蓋得住。

這一點是本提案與 2026-07-29 初次記錄時最大的差別，也是當時決定「再累積幾筆再提」的收穫。

## 2. 選項

### 選項 A：在 `evidence` 定義第三種前綴 `~`（建議）

```
~PMID:39494362    表示該文獻不足以支持或反駁本主張，但與其來源相關
```

- 優點：不動欄位數、不動欄位順序，既有解析程式讀到 `~` token 時的行為與讀到 `!` 相同（都不是支持）
- 優點：與既有的 `!` 前綴同構，agent 端只需多記一條規則
- 優點：可機器查詢「漂移來源已定位的主張有幾條」，這正是本專案的核心產出之一
- 缺點：`evidence` 一欄承載三種語意，可讀性下降。緩解方式是強制 `note` 說明不對位的維度（見 §3.1）

### 選項 B：新增 `related_refs` 欄

依 §11 往後接一欄，專記不對位文獻。

- 優點：語意分離最乾淨，`evidence` 維持「支持／反駁」的二元語意
- 缺點：121 列中目前只有 4 列會用到，117 列空欄
- 缺點：§11 明文要求 `schema_version` 遞增後前端解析與 agent 提示詞同步改。目前無前端，但欄數改動的成本是永久的
- 缺點：不對位文獻與支持／反駁文獻是**同一次檢索的產物**，分欄存放會讓「這條查過什麼」被切成兩半

### 選項 C：維持現狀，靠 `note` 說明

- 優點：不動 SCHEMA
- 缺點：不解決問題。六筆樣本已證明這不是偶發狀況，而且**這類文獻恰恰是最有價值的那一筆**——
  把最有價值的產出放在唯一不可機器讀取的欄位，方向是反的

**建議採 A。** 若日後含 `~` token 的列超過 30 條、且需要按不對位維度分類統計，
再評估升級為 B——屆時 `related_refs` 可依 §11 往後接，不影響既有欄位。

## 3. 若核准，具體改動

### 3.1 `ledger/SCHEMA.md` §4「反駁文獻」小節之後，新增小節

```markdown
### 相關但不對位的文獻

在 token 前加波浪號 `~` 表示該文獻**不足以支持或反駁**此主張，
但與該主張的來源相關：

```
PMID:31234567;~PMID:39494362
```

**判準**：一篇文獻該不該加 `~`，看的是它與 statement 之間**至少有一個維度不對位**，
而該維度的差異使它無法作為支持或反駁：

| 不對位的維度 | 範例 |
|---|---|
| 量測對象 | statement 講 syndecan-1，文獻量的是 HSPG 總體 |
| 量測方法 | statement 的數字來自 PBR，文獻用 ELLA |
| 量綱 | statement 講前導時間，文獻給的是迴歸軌跡的提前量 |
| 介入 | statement 講 HRT，文獻的介入是補充劑 |
| 族群或血管床 | statement 講腦微血管，文獻量的是舌下 |
| 時間或劑量條件 | 取樣點晚於 statement 所述的時窗，不足以反駁 |

**`~` token 的 `note` 必須寫明不對位的是哪一個維度。** 未寫明者不得使用 `~`——
一個沒有說明的 `~` 無法與「懶得判斷」區分，會使本前綴失去意義。

**`~` 不是引用轉述文獻的後門。** `queries.md` §1.6 規定僅由他篇引述得知、
未直接取得的文獻不得據以判定，此規定對 `~` 同樣適用：
未直接取得者連 `~` 都不得填入，只能寫進 `note` 並註明「未直接取得」。

**前綴可變更。** 若後續檢索確認某 `~` token 實為支持或反駁，直接改其前綴
（`~` → 無前綴 或 `~` → `!`），並在 `note` 記錄改動日期與理由。
§7 的 append-only 約束的是**識別碼本身不得移除**，不約束前綴——
前綴記錄的是判定關係，判定關係本來就會隨證據更新。
```

### 3.2 `ledger/SCHEMA.md` §4「排序」小節

現行：

```markdown
**第一個 token 為主要引用（primary reference）**，其後不拘。
```

改為：

```markdown
**第一個 token 為主要引用（primary reference）**，其後不拘。
主要引用必須是**無前綴**的支持文獻。

若該列沒有任何支持文獻（`evidence` 僅含 `!` 或 `~` token），
則該列**沒有主要引用**，將來網頁不得顯示其第一個 token 為代表文獻。
```

〔推論〕這一條是本提案最容易被忽略的副作用。`4.2.3-hrt-rct-2025` 核准後的
`evidence` 會是 `~DOI:10.14814/phy2.70428`——單一 token 且不對位。
若前端照現行規則「顯示第一個 token」，會把**一篇證明該主張沒有出處的論文**
顯示成該主張的代表文獻，方向完全相反。目前無前端，但這條規則必須先立，
否則將來寫前端的人（或 agent）沒有任何線索知道有這個坑。

### 3.3 `ledger/SCHEMA.md` §5 `tier` 規則

現行：

```markdown
`tier` 反映 `evidence` 中**未加 `!` 前綴**的 token 裡，證據等級最高的那一篇。
**反駁文獻（`!` 前綴）不計入 `tier`。**
```

改為：

```markdown
`tier` 反映 `evidence` 中**未加任何前綴**的 token 裡，證據等級最高的那一篇。
**反駁文獻（`!`）與不對位文獻（`~`）均不計入 `tier`。**
```

〔推論〕這一處若漏改，`~` 會產生與 v2 修掉的那個 bug **完全同型**的失效：
`4.2.3-hrt-rct-2025` 的 `~DOI:10.14814/phy2.70428` 是一篇 RCT 的事後分析，
照現行字面會把一條 `unsupported` 的主張標成 `tier=rct`。
v2 修的是「反駁越有力 tier 越高」，此處是「來源找得越準 tier 越高」——
同一個結構，換一個前綴。

### 3.4 `ledger/SCHEMA.md` §5 `status` 規則

`~` token **不影響 `status`**。`status` 僅由支持與反駁文獻決定。
在 §5 的 `status` 合法值表下方加一行：

```markdown
`~` 前綴的不對位文獻不影響 `status`。一列可以同時是 `unsupported`
（無任何支持文獻）且含有 `~` token（漂移來源已定位）——
這兩件事不衝突，而且同時成立時該列的資訊量最高。
```
