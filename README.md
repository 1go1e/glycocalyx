# glycocalyx

內皮糖萼（endothelial glycocalyx, eGC）文獻查證帳本。

這個 repo 做一件事：把一批關於內皮糖萼的中文文獻整理稿拆成可個別查證的**主張**，
逐條回 PubMed 找出處，把判定結果記進一個有版本規範的帳本，並保留完整的查證軌跡。

---

## 先讀這個：`verified` 的意思

**`verified` 是文獻學意義的「找得到出處」，不是臨床意義的「已驗證可用」。**

一條主張被判為 `verified`，只代表本專案在檢索中找到了與該敘述相符的原始文獻，
並記下了 PMID 或 DOI。它不代表該結論已被臨床採納、不代表證據等級高、
更不代表可以據以做任何醫療決定。

**本專案不提供診療建議。** PBR、GlycoCheck、syndecan-1 等一律為研究用指標。
因此帳本裡也**不會有任何具體劑量、給藥途徑或用藥時程**——
劑量資訊只寫在 `note` 供追溯，不會取得 `status`。理由見 `CLAUDE.md` 第 6 條：
一個帶著驗證標記的劑量，讀者會理解為「可以照做」。

## 現況

`STATUS.md` 是唯一的入口，包含帳本統計、已完成批次、待決事項與下一批。
帳本目前 121 列，多數尚未查證——這是進行中的專案。

各狀態的意思：

| status | 意思 |
|---|---|
| `unverified` | 尚未檢索 |
| `verified` | 找到相符的原始文獻 |
| `partial` | 方向或部分成立，但某個要素（數值、條件、歸屬）不成立 |
| `contested` | 找到的文獻彼此衝突，或支持文獻的對照組推翻了該主張 |
| `unsupported` | 多次不同措辭檢索後仍查無出處 |

**`unsupported` 是合格結果，不是失敗。** 這個專案的正確產出經常是「查不到」。

## 為什麼要做

原始材料是 LLM 生成的長篇整理稿。它們的內容大致正確，錯的地方卻不是隨機的——
反覆出現的是幾種**結構性的轉述錯誤**，而且每一種都比單純的事實錯誤更難察覺。
`STATUS.md` §3 記錄了目前找到的十五種，例如：

- **逆向指標被寫反**：PBR 數值越高代表糖萼越薄，被當成厚度直接引用
- **通則範圍被接到論文的研究對象上**：一篇研究腦與腎的論文在引言引了與器官無關的通則數值，
  兩者在同一頁上，接起來就成立——而那個連接不存在於任何一份文獻裡
- **兩個相反的過程共用同一個數字**：「敗血症 30 分鐘內脫落」的 30 分鐘真實存在於敗血症文獻，
  但指的是治療性**修復**的時間。數字是真的、疾病是真的、文獻是真的，只有動詞是假的
- **類別層級的數值被寫成該類別中最有名成員的屬性**

這些錯誤有個共同點：**數值查核抓不到它們**，因為要查核的東西不在數值裡。
記錄模式比記錄個案有用——後續章節可以預期它們重複出現。

## 結構

```
STATUS.md          專案現況、下一批、待決事項。從這裡開始讀
CLAUDE.md          給 agent 的專案指令與不可違反的規則
ledger/
  claims.csv       主張帳本（UTF-8 no BOM、LF）
  SCHEMA.md        欄位規則與寫入限制（唯讀，變更須提案）
  CHANGELOG.md     schema 變更紀錄
  queries.md       實測檢索式與檢索通則（經驗紀錄，非規格）
runbooks/
  backfill.md      回填作業程序
  source-editing.md 受追蹤原文的修改規範
source/            原始文件。依主題分子目錄，intake/ 為原始存檔
reports/
  backfill/        批次查證報告
  revisions/       修訂提案，需人工核准後才執行
inbox/             檢索原始回傳，保留不刪減
```

---

## 運作方式

- **原文不刪除。** 查無出處的數值一律在原地標註，不從來源文件刪掉——
  刪了就失去「原文當初是這樣寫的」這個事實
- **人工核准。** 任何 schema 變更或原文修改都要先寫提案到 `reports/revisions/`，
  核准後才執行
- **識別碼不得憑記憶寫出。** PMID / DOI 只能來自檢索工具當次回傳的結構化欄位
- **帳本不刪列。** 判定改變時新增列並標記取代關係，舊列保留
