## 2. 這張表的倍數與文獻的實測值差一個數量級

檢索過程中蒐集到的**實測** heparanase 誘導或上升幅度：

```
1.49–1.71 倍   OIR 小鼠視網膜（mRNA 與蛋白）        PMC3388984
3–5 倍         heparanase → VEGF-C                  PMID:18798279
3–6 倍         heparanase → VEGF                    PMID:16452201
> 6 倍         急性胰臟炎胰臟組織                    DOI:10.1038/s41598-017-00715-6
5.03–8.9 倍    發炎性乳癌組織 vs 對照                PMC7852308
```

而 `§6.4` 表給的是 5–20、5–15、10–50、10–30、5–10、5–20、10–100。
**下界與文獻實測值的上界相當，上界高出一個數量級。**

〔推論〕這與 `STATUS.md` §3.21 是同一族但形狀不同。§3.21 是「有一個數值、
需要第二個，於是乘一個係數」；本例是**整組數值的量級與該領域的實測分布不相容**。
七個因子的生物學機制迥異（荷爾蒙、細胞激素、缺氧、轉錄因子），
卻全部落在 5–100 這個窄帶裡且都以整數為界，
這種齊整度在真實的跨研究彙整中不會出現——真實彙整會像上面那張表一樣參差。

〔注意〕本批**不判定該表是編造的**。無出處只能寫 `unsupported`，
「像是編的」不是 status 的合法值。上述為推論，記於此供人工裁示。

## 3. 一個字面命中的陷阱

檢索 `"heparanase" "10-50 fold"` 確實命中一筆字面相符的結果——
PLOS One 2016 的 hepcidin 研究寫著「induction of the 50-kDa-active HPA form ranged
from 10 to 50 fold」。

但那是**轉染質體造成的 heparanase 過度表現幅度**（HepG2 等肝癌細胞株），
不是 TNF-α 或 IL-1β 的誘導倍數。量測對象（外源質體 vs 內源基因）與介入
（轉染 vs 細胞激素刺激）兩個維度都不對位。

〔注意〕這正是 `queries.md` §1.2 記錄的陷阱型態（endocan 77%/70% vs 78.7%/70.3%）
在倍數上的版本。**若只比對數字，這一列會被誤判為 `verified`。**
依 SCHEMA §4，兩個維度不對位到這種程度連 `~` 都不填——
`~` 是「相關但不對位」，這一筆是「不相關而字面相同」。

## 4. 方向被寫反的可能

`4.1.3-vegf-5-10x` 稱 VEGF 誘導 heparanase 5-10 倍。
文獻密集記載的是**相反方向**：heparanase 過度表現使 VEGF 上升 3-6 倍
（PMID:16452201）、使 VEGF-C 上升 3-5 倍（PMID:18798279）。

〔推論〕statement 的 5-10 與這兩個實測範圍相鄰而方向相反，
**很可能是把 heparanase→VEGF 的倍數反寫成 VEGF→heparanase。**

該列的 `evidence` 兩個 token 都加 `!`，因為它們反駁的是**因果方向**而非數值本身；
依 SCHEMA §5，反駁 token 不提升 `tier`，故 `tier` 留空。

〔注意〕同表的 `4.1.3-vegf-positive-feedback`（VEGF 與 heparanase 形成正回饋迴圈）
在此獲得**部分**支持——迴圈的一半（heparanase→VEGF）確有實證，另一半沒有。
該列為 `med`，不在本批，留給下一批。

## 5. schema 目前無法表達的一種情形

兩列遇到同一個問題：**同一篇文獻同時支持 statement 的一部分、反駁另一部分**，
而 SCHEMA §4 的 token 前綴每篇只能取一個值。

```
4.1.3-hyperglycemia-ages-rage-nfkb
  DOI:10.1007/s11010-011-0804-7 支持「RAGE」一段（RAGE 中和抗體可消除誘導）
  同一篇      反駁「NF-κB」一段（NF-κB 抑制劑不影響誘導，實際轉錄因子是 FOXO4）

4.1.3-egr1-10-100x
  PMID:16093249 對「倍數」不對位（~），對「無條件誘導」在黑色素瘤中相反（!）
```

本批的處置是各取一個前綴，另一半只由 `note` 承載。這可行但不理想——
`note` 是自由文字，不會被任何檢查或將來的前端讀到。

〔推論〕成因是 `evidence` 的 token 綁的是**文獻**，而支持與反駁的對象是
**statement 的某個部分**。真正的解法是拆列（SCHEMA §6 的拆列程序）：
`4.1.3-hyperglycemia-ages-rage-nfkb` 拆成「經 RAGE」與「經 NF-κB」兩列，
前者 `verified`、後者 `unsupported`，前綴問題就消失了。

**建議提交決策**：是否對「含兩段路徑的機制列」啟用拆列。
本批未自行拆——`runbooks/backfill.md` §3 的拆列檢查說「已判定才發現者，
判定照常寫入，拆列另案處理」，本批照此辦理。
