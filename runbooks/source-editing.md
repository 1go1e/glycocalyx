# source-editing.md — 受追蹤原文的修改規範

```
last_updated: 2026-07-30
applies_to: source/glycocalyx/v3.md
            source/glycocalyx/heparanase.md
            source/mitochondria/axis.md
不適用:     source/intake/**（原始存檔，任何情況下不修改）
```

> **給 agent：修改 `source/` 下任何受追蹤檔之前，必須先完整讀過本檔。**
> 任何原文改動都須先寫修訂單到 `reports/revisions/` 並停下等待人工核准，
> 不得直接改（`CLAUDE.md` 不可違反第 2 條）。本檔不得由 agent 自行修改。

本檔收攏三處原本分散的規則。收攏的來源一字不動，本檔以重述形式承接：

| 規則 | 原出處 | 核准日 |
|---|---|---|
| 標註格式（散文段落） | `reports/revisions/2026-07-27-source-2.1.1-thickness.md` §2 | 2026-07-28 |
| 標註格式（表格） | `STATUS.md` §5「已定調的政策」 | 2026-07-29 |
| 刪除措辭 | `reports/revisions/2026-07-30-rhetoric-policy.md` | 2026-07-30 |

〔推論〕收攏的理由不是整齊：前兩處分別是**已核准提案**與**每批都在改的動態檔**。
前者依 `STATUS.md` §3.8 屬歷史紀錄、不得修改，卻同時是每批要照著執行的活規則；
2026-07-29 補表格格式時已經因此被迫另寫一處。再補第三次會落到第三個地方，
執行者將無法一次找齊規則。

---

## 1. 三種允許的改動類型

| 類型 | 動到原句 | 需要的前置 |
|---|---|---|
| **標註** | 否——原句原樣保留，標記以獨立段落加在其後 | ledger 有對應判定 |
| **改寫** | 是——整段重寫 | 該段觸發 §2 第 4 點的密度條款，或另有核准 |
| **刪除措辭** | 是——只刪字，不重組句子 | 符合 §3 的限定條件 |

除此之外的原文改動一律不允許，包括「順手修正錯字」。

---

## 2. 標註

1. 查無出處的數值**一律標註，不從原文刪除**（人工裁示 2026-07-27）。
   此政策推翻了 2026-07-26 的 5.5 批次報告中「建議直接刪除敏感度／特異度欄位」的建議

2. 三種標記對應 ledger 的 `status`：

   | 標記 | 對應 status |
   |---|---|
   | `⚠️ 〔查無出處｜{claim_id}｜{日期}〕` | `unsupported` |
   | `〔條件限定｜{claim_id}｜{日期}〕` | `partial` |
   | `〔有爭議｜{claim_id}｜{日期}〕` | `contested` |

   `verified` 與 `unverified` **均不標註**——尚未檢索不等於有問題，
   標了會稀釋真正的警示

3. **標記不得刪除或改寫原句。** 原句原樣保留，標記以獨立段落加在其後

4. 若同一段落需要三個以上標記，代表該段應整段改寫，另寫修訂單，不靠標記硬撐

5. **表格**：新增「查證狀態」欄，不用儲存格內尾隨、不用表格下方附註。
   原有欄位與所有數值一字不動，標記寫進新增欄。
   「段落」在表格上**以整張表為單位**——四列的表有四個標記即觸發第 4 點

〔推論〕第 3 點是整套政策能否成立的關鍵：允許「標註時順手改一下」，
標註與改寫的界線會在幾次批次內消失。

〔推論〕第 5 點選新增欄而非儲存格內尾隨，理由是它讓「整表皆中」一眼可見。
標記散在儲存格裡讀者要逐格找；獨立成欄時，整欄滿的視覺效果本身就是訊息。
代價是動了表格結構，故每次仍須個別核准。

## 3. 刪除措辭

新增於 2026-07-30，依 `reports/revisions/2026-07-30-rhetoric-policy.md`（核准 2026-07-30）。

### 3.1 只有一類措辭可以刪

**純評價性時間形容詞**：`最新`、`近年`、`近期`、`最近`、`截至`、
`新興`、`新近`、`目前`、`當前`。

限定條件，三者須同時成立：

1. 刪除後句子仍然通順
2. 刪除後語意不變
3. 該處**未同時**命中 §3.2 的任何一類

不成立時**不刪**，改依 §3.2 處理。

```
可刪：近年來的糖生物學研究將焦點轉向「硫酸化品質」
    → 糖生物學研究將焦點轉向「硫酸化品質」

不可刪：eGC 降解目前被公認為敗血症、糖尿病中的早期損傷
        「目前」是可刪類，但「公認」屬 §3.2，整句依 §3.2 處理
```

### 3.2 不可刪，改為抽成 claim 去查

以下三類**原句一字不動**，把宣稱本身抽成一條 claim 走回填流程，
依 `ledger/SCHEMA.md` §6 寫成可查核形式，查不到具名來源即 `unsupported`，
再依 §2 加標註。

| 類 | 例 | 為什麼不能刪 |
|---|---|---|
| **年份＋文獻類型** | 「2025 年的薈萃分析指出」 | 年份是該句僅存的溯源線索，刪掉就再也追不回來 |
| **未具名權威宣稱** | 「國際共識」「新典範」「臨床標準」「金標準」 | `SCHEMA.md` §6 已明文規定處置方式 |
| **無主詞措辭** | 「研究顯示」「文獻報告」「一般認為」 | 同上 |

〔推論〕年份那類的毛病不是「有年份」，是**只有年份**——沒有作者、沒有期刊、
沒有識別碼。它與未具名權威是同一個問題，只是宣稱的載體換了。
把它當措辭刪掉，等於把一個可查證的宣稱變成不可查證的。

### 3.3 一句同時命中多類時的優先序

```
未具名權威 > 年份＋文獻類型 > 無主詞措辭 > 純評價性形容詞
```

以最重的一類為準。一旦決定不動原句，句中的可刪形容詞也一併留著——
否則會出現「同一句刪了一半」的狀態，日後無從判斷是有意還是漏改。

### 3.4 掃描方式

正則字面見 `ledger/queries.md` §6。兩件必須照做：
`adj` 與 `year` 分開計數（處置相反）；以行內排除跳過專案自己加的標註
（標記文字本身含「共識」等詞，會造成假陽性）。

## 4. 檔頭的收錄基準

三個受追蹤檔的標頭各加一行：

```
> 本檔為 LLM 產出文件，2026-07-28 收錄。文中未標註年份的時間表述以此日為基準。
```

這處理的是**未來新增**的時間形容詞，不取代 §3.1 的刪除。

---

## 5. 執行與驗證

每次原文改動須在修訂單裡逐行列出改前／改後，執行後驗證並記錄：

- 改動前後行數
- 逐字保留的行數
- 未對應的行數（應為 0）
- **原檔所有數值無一消失**

前例：`reports/revisions/2026-07-27-source-2.1.1-thickness.md`、
`reports/revisions/2026-07-29-source-2.2-5.1-5.5.md`。

## 6. 本檔與 `ledger/SCHEMA.md` 的分工

| | 管什麼 | 版本 |
|---|---|---|
| `ledger/SCHEMA.md` | `claims.csv` 的欄位與寫入規則 | `schema_version` |
| 本檔 | `source/` 受追蹤檔的改動規則 | `last_updated` |

**本檔的變更不遞增 `schema_version`。** `schema_version` 是 `claims.csv` 的格式契約，
原文措辭不在契約裡。用版本號記錄非 CSV 的變更，會讓日後任何人無法憑版本號
判斷 CSV 到底變了沒有。
